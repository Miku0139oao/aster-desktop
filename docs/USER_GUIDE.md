## 安裝與升級

所有檔案均從[正式發佈頁](https://github.com/Miku0139oao/aster-desktop/releases/tag/v0.2.3)下載；核對系統及處理器種類。頁面中的 `source.zip`／`source.tar.gz` 是原始碼，不能直接當作桌面程式執行。`Aster-Desktop-0.2.3-docs.zip` 是離線文件，解壓後用瀏覽器開啟 `index.html`，不需要安裝閱讀工具。

### Windows

1. 升級前先在右下角托盤找到 Aster，右鍵選「退出」。關閉主視窗會留在托盤。
2. 執行 `Aster-Desktop-0.2.3-windows-x64-setup.exe`，依畫面完成安裝及管理員授權。
3. 從開始功能表開啟 Aster Desktop。原有訂閱與使用者設定會保留。已安裝背景服務者應使用安裝器升級，讓服務一起更新。

可攜版：下載 `windows-x64-portable.zip`，完整解壓到固定資料夾，再執行 `aster_desktop.exe`。不要直接在 ZIP 預覽中執行，也不要只複製 EXE；核心、橋接程式及資料夾需要放在一起。使用 TUN 仍需從 GUI 安裝背景服務。安裝版與可攜版共用同一使用者資料與多開保護。

### macOS

1. 在「關於這台 Mac」查看晶片。M 系列選 `macos-arm64.dmg`，Intel 選 `macos-amd64.dmg`。
2. 退出舊版，開啟 DMG，執行其中的 `Install Aster Desktop.pkg`。PKG 會將程式安裝到 `/Applications/Aster Desktop.app`，請使用此位置的程式。
3. 從「應用程式」開啟。套件使用本機簽署，尚未取得 Apple Developer ID 簽章／公證；若系統阻擋，確認檔案來自本專案後，到「系統設定 → 隱私權與安全性」查看允許開啟選項。不要停用整個系統的安全保護。
4. 首次使用系統代理或 TUN，依畫面安裝／授權背景服務；若顯示需要批准，到系統設定的登入項目／背景項目允許 Aster，再回程式重試。不同 macOS 版本的選項名稱可能不同。

Intel／Apple Silicon 均已通過 CI 建置與實際 PKG 安裝核對；實機網路、TUN、服務授權互動、Gatekeeper 及睡眠喚醒仍待完整驗收，詳見[測試紀錄](TESTING.md)。

### Ubuntu 與 Arch Linux

Ubuntu 24.04 請下載 `.deb`，使用系統套件安裝程式開啟。Arch 請使用套件管理員安裝 `.pkg.tar.zst`；若桌面未提供套件安裝介面，可使用 `sudo pacman -U ./Aster-Desktop-0.2.3-linux-x64.pkg.tar.zst`。安裝後從應用程式選單啟動。

可攜版請選擇與發行版相符的 `linux-ubuntu-24.04-x64-portable.tar.gz` 或 `linux-arch-x64-portable.tar.gz`，完整解壓後執行 `aster_desktop`。需要 GTK 3、對應 AppIndicator、polkit 授權代理；TUN 另需 systemd 背景服務。GNOME 顯示托盤圖示可能需要桌面端的 AppIndicator 支援。無可用托盤時，關窗會執行退出。

### 核對下載檔案

需要校驗時，下載同一發佈頁的 `SHA256SUMS`，將檔案 SHA-256 與其中同名項目比較。

- Windows PowerShell：`Get-FileHash .\Aster-Desktop-0.2.3-windows-x64-setup.exe -Algorithm SHA256`。
- macOS：`shasum -a 256 Aster-Desktop-0.2.3-macos-arm64.dmg`。
- Linux：`sha256sum Aster-Desktop-0.2.3-linux-x64.deb`。

## 第一次連線

1. 首頁按「匯入訂閱或設定」。
2. 挑選一種匯入方式：

| 你手上的內容 | 選擇 |
| --- | --- |
| `https://…` 訂閱網址 | 訂閱網址 |
| 一個或多個節點分享連結、明文／Base64 訂閱、完整 YAML 文字 | 貼上內容 |
| 本機 `.yaml`／`.yml`／`.txt` 檔案 | 設定檔 → 選擇設定檔 |

3. 名稱可自行填寫，按「匯入並檢查」。支援 SS、VMess、VLESS、Trojan、HY2、TUIC、AnyTLS（含 REALITY）及 Clash YAML。部分連結無效時，請查看匯入警告及對應行號。
4. 前往「節點」，在群組中選一個節點。首次可以保留預設選擇；遠端 provider 的節點在核心啟動後載入。
5. 回首頁，保持預設「系統代理」，按「開始連線」。也可在目前頁面直接按側欄「啟動代理」。
6. 首頁顯示「已連線」後，在瀏覽器開啟你要使用的網站；若不通，前往「診斷 → 開始診斷」。已連線代表核心啟動成功，仍需實際請求確認節點與網路可用。

若目前網路必須經代理才能下載訂閱，可先透過「貼上內容」匯入一個可用節點，連線後再匯入網址。不要把訂閱帳密或完整連結貼到公開問題回報。

## 系統代理與 TUN

先停止代理，再變更首頁的連線方式或 TUN 出口網路。

| 連線方式 | 適合的情況 |
| --- | --- |
| 系統代理 | 一般瀏覽器及遵循系統代理設定的程式；建議先使用 |
| 代理所有應用程式（TUN） | 遊戲、自訂網路程式、需要按應用程式分流的情況；需系統授權 |
| 兩者均關閉（手動代理） | 自行在應用程式指定進階設定顯示的本機代理位址／連接埠 |

開啟 TUN 不代表所有流量都會走同一節點；它將應用程式流量接入核心，出口仍由下方模式與規則決定。不遵循系統代理的程式，僅開「系統代理」通常無法接管。

### 啟用 TUN

1. 停止代理，開啟首頁「代理所有應用程式」。
2. 若顯示「首次使用需要背景服務授權」，按「安裝／授權」並完成作業系統提示；也可在「進階設定 → 背景服務」管理。拒絕授權時，可先回到系統代理使用。
3. 「出口網路」通常保留自動偵測；若同時連接 Wi-Fi 與無法上網的有線網路，明確選擇可上網的 Wi-Fi。這項設定控制 TUN 核心的節點／DNS／訂閱出口，不修改整台電腦的路由優先權。
4. 再按「開始連線」。切換網路或睡眠喚醒後若無法上網，先停止、確認出口介面仍在線，再重新連線。

### 選擇出口模式

| 首頁選項 | 行為 |
| --- | --- |
| 依規則 | 依設定檔與應用程式規則選擇代理、直連或封鎖；日常分流建議使用 |
| 全部代理 | 使用全域群組（GLOBAL）所選出口；應用程式規則不決定出口 |
| 全部直連 | 直接連線，不經代理節點 |

「全部代理」只作用於進入核心的流量。若希望不遵循系統代理的程式也進入核心，需要 TUN。

## 選擇節點與群組

「節點」頁按群組展示。點卡片／列表中的節點切換選擇；可使用搜尋、群組篩選、協定／provider 篩選、收藏與最近使用縮小清單。工具列可切卡片／列表，依設定順序、名稱或延遲排序。離線也能選本機匯入的節點，連線後會套用。

延遲數字或卡片右鍵可測單個節點，也能對群組測試；測速設定可調測試網址、逾時及同時測試數。這裡的「測速」是請求延遲，不是頻寬下載測試；低延遲也不保證所有網站都可連線。測試需要核心運作，遠端 provider 需先載入。

自動測速／故障切換群組可先固定節點，再按「恢復自動選擇」交回群組決定。「管理」可新增、編輯、複製、刪除節點與群組，也能管理節點／規則 provider。

## 訂閱與設定管理

在「訂閱與設定」可保存多份設定，標記「使用中」的是目前使用的一份。

- **使用此設定**：切換目前設定。
- **更新訂閱**：先預覽新增、移除與變更，再按「套用更新」；下載或驗證失敗保留舊內容。
- **名稱與排程**：修改名稱／來源，選跟隨全域排程、個別排程或僅手動。全域排程在進階設定。
- **複製為本機設定**：產生獨立副本，適合較大的手動修改。
- **編輯設定／匯出／刪除**：編輯 YAML，將設定保存到檔案，或移除該份設定。

訂閱有提供使用量及到期資訊時，頁面會顯示；沒有回傳這些資料時無法推算。GUI 建立的節點／DNS／分流覆寫及停用規則會在訂閱更新後保留。直接改動訂閱原始 YAML 的內容可能被下一次來源更新取代，長期自訂建議使用 GUI 管理或複製為本機設定。

## 應用程式與分流規則

例如讓瀏覽器走某個節點、另一個程式直連：

1. 在首頁啟用 **代理所有應用程式（TUN）** 並選 **依規則**，連線後可載入遠端節點。
2. 開啟「應用程式 → 新增應用程式」。從「應用程式」、「正在執行」或「所有程序」清單搜尋、選取程式。
3. 選出口：代理群組、具體節點、DIRECT（直連）或 REJECT（封鎖）。點群組卡片跟隨群組，點箭頭進群組挑節點。
4. 對其他程式重複上述步驟；「多選程式，套用同一出口」可批次處理。既有規則可直接修改出口或移除。
5. 讓該程式重新建立網路連線。規則適用於新連線，已建立的連線不會自動搬到新出口；必要時可在連線頁中止它，再由程式重連。

選群組會跟隨該群組的共同選擇；固定 provider 的具體節點則保持該程式獨立出口。固定節點從訂閱消失時會封鎖該路由，請重新選擇。

清單按實際執行檔路徑辨識。同名程式、啟動器與網路輔助程序可能是不同項目；找不到時先啟動程式，重新整理後從「正在執行」選取，或瀏覽其他執行檔。Mac 可選 `.app`。程式更新後若安裝路徑改變，請重新選取。詳見[應用程式分流](APPLICATION_ROUTING.md)。

「規則」頁管理網域／IP／程序分流與順序。新增規則會優先於現有規則，適用於新連線。也可從「連線」明細直接建立規則，減少手動輸入。

## 連線、日誌與流量

### 連線

查看即時速度、核心累計及活動連線；依程式／目的地搜尋，搭配 TCP／UDP、出口、入口篩選，或依程式／出口彙整。小視窗按「更多篩選」展開。點選連線查看程序完整路徑、目的 IP、出口鏈、命中規則與流量；可複製、建立規則或中止。中止會打斷請求，應用程式可能自行重連。

暫停列表方便閱讀，不會停止網路或流量統計。未知程序表示核心未取得足夠資料；若流量經另一個本機代理轉接，看到的程序可能就是該代理。

### 日誌

按層級、來源及關鍵字篩選。點單筆看完整原文；捲動或開明細時會暫停列表，閱讀完按播放／「回到即時日誌」追蹤最新內容。複製／匯出的是目前篩選結果。

多個詞以 AND 組合，`-` 排除詞，雙引號保留片語。例如 `dial timeout -udp`、`level:warning source:core`；連線可用 `app:browser host:example.com`。完整欄位見[日誌與連線查閱](INSPECTION.md)。核心日誌層級決定實際產生的紀錄，選 info 不能補回未記錄的內容。

### 統計

首頁與連線頁的累計流量是本次核心啟動的計數，重啟核心會歸零。「統計」頁在本機保存最多 365 天的每日總量，可選今日／7 日／30 日／一年並匯出 CSV。應用程式與出口分類為每 5 秒取樣，短連線可能遺漏，不能作為訂閱帳單。正常退出保存最後資料，異常退出可能遺失最近約 20 秒。

## DNS、YAML 與備份

「進階設定 → 網路與分流」提供 DNS、本機代理連接埠與區域網路存取。連接埠需先停止代理再修改；只有需要其他裝置使用這台電腦的代理時才開放區域網路。

完整 YAML 可從「訂閱與設定 → 編輯設定」，或「進階設定 → 編輯完整 YAML」開啟。

1. 修改後先按「檢查設定」。
2. 按「儲存並套用」；程式會驗證並自動備份，失敗保留上一份有效設定。
3. 要回復最近一次修改，按「還原上一份」。

「還原上一份」是單步回復，不代替長期備份。重要修改前先從訂閱頁「匯出」另存原始 YAML，之後可從「匯入 → 設定檔」匯入。這項匯出只保存 YAML，不能視為包含所有桌面偏好、歷史流量與 GUI 分流資料的完整備份。

原始匯入設定與桌面管理設定分開保存；Controller、密碼、執行路徑、桌面連接埠、模式、TUN 等由 GUI 管理。這些桌面選項應從首頁／進階設定修改。只有節點的訂閱會自動產生基本群組及規則，完整設定則保留其群組與規則。高權限 TUN 對本機 provider／憑證檔案有路徑限制，遇到這類驗證錯誤請見[FAQ](FAQ.md#yaml-或-provider-驗證失敗)。

備份、YAML、訂閱 URL 可能包含 token、帳密與節點資訊，請存放在私人位置。日誌／診斷匯出雖有常見憑證遮蔽，公開前仍需檢查內容。

## 更新、退出與移除

### 更新桌面程式

「進階設定 → 檢查更新」提供 GUI 正式版資訊與下載入口；也可直接到[發佈頁](https://github.com/Miku0139oao/aster-desktop/releases/latest)。下載對應安裝包後，先從托盤「退出」，再安裝。0.2.3 正式版沿用 0.2.3 beta 1 的同一套二進位資產，已使用該版本者不必重裝。

### 更新核心

在「進階設定 → 檢查更新」操作核心更新。核心追蹤官方 `Prerelease-main`，只有按下更新才執行。GUI 與核心分別版本化，更新核心不會替換介面或分享連結轉換器。

可以保持系統代理或 TUN 連線更新，GitHub 下載會經目前代理；下載及 SHA-256／架構／設定／API 驗證完成後才短暫重啟並恢復模式、節點與連線。下載或驗證失敗保留舊版，新版啟動失敗會回復。背景服務與一般核心分別驗證；若其中一份失敗，請保留錯誤資訊並在診斷頁查看服務狀態。

### 關窗、退出與自啟

- **關閉視窗**：有托盤時隱藏到托盤，代理保持連線；點托盤或重新啟動程式可喚回。
- **停止代理**：斷線並還原由 Aster 管理的系統代理，GUI 保持開啟。
- **退出**：托盤選「退出」，先停止核心、還原代理、關閉背景連線，再結束 GUI。Mac Dock「結束」／⌘Q 也會走清理流程。
- **登入自啟**：預設關閉。開啟「進階設定 → 登入後自動啟動並連線」後，登入時使用目前選擇的設定。

### 移除

先停止代理；需要移除 TUN 服務時，到「進階設定 → 背景服務 → 移除服務」完成系統授權，再從托盤退出。Windows 用系統「已安裝的應用程式」解除安裝，Linux 用套件管理員，Mac 移除 Applications 中的程式。可攜版退出後可移除解壓目錄。

移除程式會保留使用者設定，方便重新安裝。設定位於作業系統的應用程式支援目錄；請勿直接刪除正在使用的資料。若需要搬移或清除完整資料，先備份並退出，再依[架構說明](ARCHITECTURE.md)與實際安裝位置確認。
