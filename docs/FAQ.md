# 常見問題與故障排除

[使用手冊](USER_GUIDE.md) · [回首頁](../README.md) · [回報問題](https://github.com/Miku0139oao/aster-desktop/issues)

## 顯示已連線，但無法上網

1. 先確認目前節點與模式。若選「全部直連」，流量不會使用代理節點。換一個可用節點，並讓目標程式重新建立連線。
2. 到「診斷 → 開始診斷」，查看核心、服務、出口網路、系統 DNS、系統路由請求及本機代理 HTTPS 哪一步失敗。診斷會發出 DNS／HTTPS 測試，不會修改系統網路設定。
3. 系統代理正常而某個程式仍不通，可能該程式不遵循系統代理；改用 TUN。TUN 不通時，先依下一節排除。
4. 到「日誌」以 warning／error、`dial`、`timeout` 等搜尋，展開錯誤原文。測速通過只是測試網址可用，不代表所有網站可用。

本機代理 HTTPS 通過不等於 TUN 路由正常；系統路由診斷也不能證明每一個應用程式都被接管。

## 系統代理可用，TUN 卻不通

先停止代理，確認「進階設定 → 背景服務」已安裝並授權。開啟首頁「代理所有應用程式」，檢查「出口網路」。多網卡環境請選真正可上網的 Wi-Fi／有線介面；自動偵測可能選到已連接但沒有網際網路的介面。換網路後重新確認所選介面仍在線，再連線。

若同時使用其他 VPN／代理程式，先檢查是否共同接管路由或 DNS。可暫時回到系統代理保留日常使用，再附上出口介面、診斷與核心錯誤回報；不要直接修改或清空整台電腦的路由表。

## 背景服務授權被拒絕，或找不到服務

停止代理後，在首頁「安裝／授權」或「進階設定 → 背景服務」重試，完成 Windows 管理員／macOS 背景項目／Linux polkit 提示。沒有授權時可先使用系統代理（Mac 系統代理同樣需要助手授權）。

Mac 請從 `/Applications/Aster Desktop.app` 啟動，並查看系統設定中的背景項目是否允許。Linux 需 systemd 與運作中的桌面 polkit 授權代理。升級已安裝的 Windows 版本時請使用安裝器，僅替換可攜版 GUI 不會更新既有背景服務。

## 核心已停止／Core stopped

這是狀態提示。若尚未按連線，核心停止屬正常。若連線後立刻停止，先查看首頁展開的技術細節與「日誌」，再檢查使用中設定、連接埠、服務授權及出口網路。新安裝若提示缺少核心，重新安裝完整套件，或完整解壓可攜版；不要只複製 GUI 執行檔。

## 匯入或更新訂閱失敗

確認 URL 是訂閱來源，而不是需要登入的網頁；來源若回傳 HTML、過期／拒絕存取頁面，無法當作節點使用。多個分享連結可用「貼上內容」匯入，查看逐行警告。節點重複名稱會加序號。

若下載需要代理，先匯入可用的本機設定或分享連結並連線，再更新網址。更新失敗會保留舊內容；預覽後設定已變動時，請重新預覽，避免覆蓋新修改。

## 應用程式不在清單，或分流沒有生效

先啟動該程式，再重新整理並選「正在執行」；也可瀏覽執行檔（Mac 可選 `.app`）。清單以實際執行檔路徑比對，啟動器、商店程式、Flatpak／Snap 或網路輔助程序不一定能由捷徑判斷，請從執行中的清單確認。安裝清單快取約 30 秒。

分流需使用 **TUN + 依規則**，且適用於新連線；修改後讓程式重連，或在「連線」頁中止舊連線。若程式更新改變路徑，請重新選擇並移除舊規則。固定的 provider 節點消失時，改選可用節點或群組。

## 連線顯示 Aster 或未知程序

程序資訊來自核心查詢 socket 擁有者。Aster 自己的節點、DNS、訂閱請求可能顯示自身；可使用連線頁隱藏自身連線。其他本機代理轉接的請求可能只能辨識到該代理；未知表示資料不足，並不會猜成原始程式。完整路徑與入口、出口鏈可從明細查看。

## 日誌沒有新內容，或篩選後空白

先清除搜尋及層級／來源篩選，再按播放或「回到即時日誌」。捲動／開明細會暫停畫面，方便閱讀。核心設定為 warning 時不會產生 info，即使在日誌頁勾選 info 也無法補回。只保留有限緩衝，不是長期完整日誌。

## YAML 或 provider 驗證失敗

先按「檢查設定」並查看錯誤。檢查 YAML 縮排、節點／群組引用與檔案格式。修改失敗保留舊設定；需要撤銷最近修改時用「還原上一份」。

完整設定可保留 DNS／群組／規則，但桌面 Controller、執行路徑、模式、連接埠與 TUN 由 GUI 管理。HTTP provider 快取路徑由程式管理；本機 file provider 由檔案匯入時內嵌。本機 MRS 規則需改為 HTTP provider、文字／YAML 或內嵌。高權限 TUN 不接受任意本機憑證／檔案路徑，請使用內嵌內容。

## 更新需要 GitHub，是否必須先斷線

更新核心可以保持系統代理／TUN，下載與驗證會使用目前代理；驗證成功後才短暫重啟。下載失敗、checksum 不符或驗證失敗會保留舊版。若所選節點無法存取 GitHub，可換節點再試。桌面安裝包更新則須先下載，從托盤「退出」，再執行安裝器。

## 關窗後還在運作，或安裝器要求先退出

關閉視窗會留在托盤，代理繼續運作。升級前請從右下角／選單列托盤選「退出」，等待清理完成；Mac 也可用 Dock 結束／⌘Q。再次啟動只會顯示既有視窗。

若已退出仍被安裝器阻擋，確認另一個使用者工作階段是否仍開著 Aster，並等待舊程序完成清理。0.2.3 已修正已結束程序殘影造成的誤判；仍有問題時請回報系統版本、安裝器版本及提示原文，不需要先刪除設定或強制停掉不明系統程序。

## 流量為什麼和訂閱帳單不同

首頁是本次核心累計，核心重啟會歸零；「統計」是本機保存的每日歷史。應用程式／出口分類採樣，可能遺漏短連線；供應商也可能使用不同計費方式。請以供應商帳單為準。

## 如何回報問題

到 [GitHub Issues](https://github.com/Miku0139oao/aster-desktop/issues) 提供系統及處理器、Aster Desktop／Core 版本、系統代理或 TUN、使用網路介面、重現步驟、預期／實際結果與錯誤原文。「診斷 → 匯出診斷」及日誌篩選匯出可補充資訊。

公開前檢查檔案，移除訂閱 token、分享連結、密碼、真實節點及私人路徑。自動遮蔽只處理已知格式，無法保證任意內容沒有私人資料。不必提交整份私人訂閱；可用已移除憑證的最小設定或畫面說明。
